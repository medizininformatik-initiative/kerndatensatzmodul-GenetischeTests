# Provenance and revision history — `mii-ig-migration`

The dated record of what changed in this skill and what measurement forced it. It lives here rather
than in `SKILL.md` because it is history: an agent activating the skill pays for the body on every
run, and none of the entries below changes what it should do. `SKILL.md`'s *Provenance* section
carries the attribution and the licence, which do not move.

**2026-08-06 — the false "Simplifier is not a scrape target" claim, corrected; the narrative harvest.** This skill stated that the Simplifier guide is client-rendered — "measured HTTP 200, ~56 KB, 52 script markers, no identity metadata in the DOM" — and therefore a human reference at Gate A, not a scrape target. **The measurement was correct and the conclusion was not: it was taken on the PROJECT page and generalised to the GUIDE pages, which are a different URL space and ARE server-rendered.** The cost was concrete: the KDS Consent migration shipped with the **template's starter pages** in place of the module's real German narrative, and nothing in the run flagged it, because a claim of impossibility is never re-checked. Re-measured 2026-08-06 — project page `https://simplifier.net/MedizininformatikInitiative-ModulConsent/` genuinely a client-rendered app shell (the original finding stands **for that URL only**); guide root `https://simplifier.net/guide/miiigmodulconsent/MIIIGModulConsent?version=2026.0.0` **HTTP 200, 24509 bytes, ~3.4 k characters of visible text**, carrying the whole page tree, **23 `href="/guide/…"` links of which 18 are pages**; guide leaf `…/Beschreibung-Modul-Consent?version=2026.0.0` **HTTP 200, 20481 bytes, ~1.4 k characters**, `<h1 id="page-title">` plus the real narrative ("Das MII KDS Modul Consent ist ein Basismodul des Kerndatensatzes (KDS) der Medizininformatik-Initiative (MII)…"). Three things the real harvest forced that a design would have missed: a page's content region must be isolated by **depth-scanning `<div>`/`</div>`** from `id="preview-content"` (a regex to the next `</div>` truncates at the first nested one and reads as a short page); a guide's page tree contains Simplifier's **rendered artefact views** (Consent's profile page is 239875 characters of generated element tree against a narrative page's ~1400), which are regenerated by the IG Publisher and must not become hand-maintained prose, so they are classified and their conversion losses reported under a separate `generated-view-lossy:` token; and the retention check itself must normalise **both** sides identically — its first version reported five intact German sentences as missing because Markdown moves a link's URL between adjacent words, because `(Projekt)` inside a URL defeated a `[^()]*` pattern, and because a page whose link text *is* a URL had that URL swept from one side only. **The general lesson, now guardrail 9 in `SKILL.md` and guardrail 10 in the spec:** a negative capability finding is only valid for the exact artefact it was measured on, is recorded with its URL/command, date and numbers, and is **never generalised to a sibling** URL or mechanism. This is the second such error in this skill — the first was the claim that the IG Publisher cannot localize page titles, which §5.5 disproved with a working `.po` recipe — which is why the rule is now binding rather than advisory.

**2026-08-06 — the rendered guide made discoverable, and a false negative retired.** §2's `SOURCE_RENDERED_IG_URL` was human-provided, and §5.1 told a reader who had none to give up on the rendering and work from the repository — on the strength of the tier-H measurement that a Simplifier **project** page is client-rendered, generalized into "Simplifier is not scrapeable". The measurement was right about that page and wrong about the platform: the package page, the project's guide listing, the version listing and the guide pages are all **server-rendered**. New **§5.1c** — which took the section number the same day's narrative harvest had held, moving that to **§5.1d**, because a guide is discovered before it is harvested — is the anonymous five-hop chain from an org key and a module name to pinned guide pages — `/organization/<org>/~projects` (23 MII package ids) → `/packages/<id>/latest` (the project slug) → **`/<project>/filterprojectguides`, no tilde** (the `~filterprojectguides` and `~guides` variants return 200 and yield nothing) → `/published-guide/<key>/versions` → `/guide/<key>?version=<v>`, whose root carries the page tree. Three rules come with it: a migration **pins a published, read-only version and records it like the source commit SHA**, because `?version=current` is the live editable project and two runs could silently differ; guide keys and page slugs are **discovered, never constructed** (measured: `miiigmodulconsent` exists, the analogously built `miiigmodulperson` 404s; the renderer de-punctuates *Anwendungsfälle / Informationsmodell* into `AnwendungsflleInformationsmodell`, and the two Consent guides have different GuideRoots); and a guide's version is **not** the module's version, so it is never claimed into the identity ledger (measured: guide 2025.0.1 carries package 2025.0.0). `scripts/simplifier-discover.sh` performs the chain and WARNs at any hop that yields nothing rather than guessing past it — measured end to end on Consent: 23 packages → project `medizininformatikinitiative-modulconsent` → **3** guide keys → 3 pinned versions → **52** page URLs, exit 0; each refusal branch exercised separately (`guide-key-not-published:` on a constructed key, `module-ambiguous:` on 23 candidates, `pinned-version-not-published:` on an absent pin). The gated project download `<project>/$actions/downloading` was re-verified as login-walled on all four query variants and its status is unchanged: an opt-in human step, never a credential mechanism the skill invents. The general rule this restates: **a negative capability finding is measured on the exact artefact it is claimed about** — the same lesson as the retired "the repository carries no narrative" overclaim in §5.1b.1.

**2026-08-06 — the measurement rule stated in both directions, and the sibling skill made a checked precondition.** Two changes, both about a claim this specification makes without the evidence it needs. **(1)** §5.1c.2's rule existed in one direction only — a negative capability finding is measured on the exact artefact it is claimed about — while three shipped defects came from the mirror image, a POSITIVE claim measured on one instance and generalised: the page-title mechanism (§5.5), first "cannot be localized" from a publisher source constant with no build at all and then a mechanism from exactly one build on one publisher version, until the HL7 `multi-lang-test-ig` on 2.0.13 with a deliberately misconfigured `/fr/` supplied a second instance and a controlled negative; "Simplifier is client-rendered, so nothing is extractable", measured on the project page (§2.1.3); and the guide-key shape `data-url="/guide/<key>"`, read on the one module where every key is bare — measured across all 23 MII modules it drops keys silently at exit 0 (consent 3 of 3, **mikrobiologie 2 of 3, person 0 of 3**). In every case the single sample was the benign one, which is the normal case rather than bad luck: the first instance to hand is the reference module, the most regular member of its class. New **§5.1c.2a** states the rule whole and gives the operational test — name the class, measure more than one instance, choose the second as the one most likely to differ (or take the whole set where it is small, or try a controlled negative), record the sample beside the claim, and bound a single-instance claim to that instance instead of widening it silently. The skill-independent form lives in the catalog's `skill-authoring` skill (`references/measurement-rule.md`), because it is an authoring rule and not a FHIR one. **(2)** Step 7 and §7's Definition of Done require `fhir-ig-analysis`' same-module verification and never said how to obtain it, leaving an operator without it to skip the check, hand-wave it or improvise. New **§5.6a** + `scripts/sibling-skill-check.sh` detect the sibling — by its frontmatter `name:`, never by its directory name — and, when it is absent, WARN `sibling-skill-unavailable:` carrying the exact **pinned** `npx skills add …/tree/<ref>` command, with the ref read from the project's own `skills-lock.json` (a recorded `main` additionally raises `pin-not-taken:`, the second independent way to see a pin that never applied). It installs nothing, deliberately: `allowed-tools` grants permission and does not express a dependency — this skill's `Bash(npx:*)` grant, there for the pinned SUSHI/goFSH runs, would equally permit the install — and auto-installing would write to the operator's project as a side effect of an unrelated run, make the run non-hermetic against a version nobody reviewed or recorded, and turn the catalog's deliberate, static-by-design pin into a run-time resolution. Every branch exercised: present → exit 0; absent → exit 1 with the command; name mismatch, `pin-not-taken:`, a `<ref>` placeholder when no lock file records one, `skill-root-undetermined:` when no skills root exists at all (reported as unread, never as absent); bad option exit 2, `--help` exit 0.

**2026-08-07 — the verification phase, and a bounded auto-fix loop.** Until now *Verification* was a list of sentences a human was asked to perform, and §7's Definition of Done was met by assertion. Four real migrations (Dokument, Person, Consent, Labor) passed that checklist on a green build while shipping, each measured on the published previews: **unreachable content** — Consent renders SearchParameter pages that `artifacts.html` did not list, which the artifact-SET comparison of `fhir-ig-analysis` cannot see because the artefacts are *present* and reachability is a different property; **stale provenance** — a rendered IG whose `Templates:` line names a different version than the tree it was built from (the same class as a published `demo/v0.5.1` directory whose pages read "Preview v0.5.0"); **a rendered metadata defect** — Dokument's `<div id="ig-status">` reads `2026.0.1 - Unknown region code '276'` while `qa.txt` reports zero errors for it; **silent truncation** — an FSH parse error stopping SUSHI mid-file while it still *exported* the instance (nested provisions 1/1/1 before repair, 6/27/3 after); **silent partial conversion** — goFSH at exit 0, "0 Errors", 1 of 20 inputs; **a wrong dependency pin** — a parent resolved from `dist-tags.latest` 2.0.3 where the source pinned 2.0.2; and **silent relicensing risk** — the template's `license: CC-BY-4.0` is a literal no placeholder check flags, over modules that declare CC0-1.0.

**What replaced it.** `scripts/verify-migration.py` runs four mechanical layers and **exits non-zero** (spec §11): conservation (present **and reachable from `artifacts.html`**; every source page migrated/retired/MISSING against the new required artefact `migration-log/page-map.tsv`; every source text run present, using the same run split and normalisation as `guide-page-to-md.py`'s `missing_runs=` so the two numbers are comparable), fidelity (identity field by field, **dependency pins against the source's**, `license` asserted from a tier in `identity-claims.tsv` or reported as unasserted), provenance (read out of the RENDERED `qa.html`), rendering integrity (empty tables/tabs, unresolvable images, header-region defect markers, and language parity on **narrative pages only**). **Three verdicts, not two** — `IDENTISCH`, `DIVERGIERT`, and **`NICHT PRÜFBAR`** with the reason and the human action, because a two-valued scheme forces every unmechanisable check to be written as a pass, which is how "the German pages render" came to be ticked on a migration nobody had built. Exit 0/1/3, and 3 is *incomplete*, not passed.

**The run log became a second oracle** (§11.6, §10.7): the log records what each step *intended and measured*, the tree records the *outcome*, and four defect classes exist only in the gap — an emitted-and-never-actioned `silent-partial-success:` WARN, **a step that emitted no line at all** (invisible everywhere else; the manifest is `references/expected-steps.tsv`), an open `identity-contradiction:`, and log-versus-artefact count mismatches (conversion, page, artifact). Two of the four real migrations had **no committed `run.log` at all**, which is now finding L0.

**Measured while building it, and encoded because it would otherwise have shipped as a confident, wrong check: the ig-template PACKAGE version and the module-template REPO release are different numbers.** Repo tag `v0.6.0` vendors `ig-template/package/package.json` version **0.5.1**; repo tag `v0.5.1` vendors **0.3.0**. Comparing a rendered `…template#0.5.1` against the release `v0.6.0` therefore produces a false finding — so P1 compares the rendered value with the *vendored package* and P2 compares the *vendored ref* (read from the run log's `5.2 skeleton-vendored … ref=` line) with the release. Two other false-positive sources were found the same way and fixed at the cause: the ImplementationGuide resource is not an artefact (no rendered page, no `artifacts.html` row) and was excluded; and image references resolve against the site root as well as the variant directory, aggregated one row per asset rather than per page — before that, a partial copy of a real site produced 60 rows for 4 real assets.

**The auto-fix loop** (`scripts/autofix-loop.sh` + `scripts/autofix-fix.py`, spec §12) is deliberately unambitious: **allowlist, never blocklist** — four classes (`gofsh-residue`, `template-example-link`, `po-missing-unit`, `revendor-template`), each mechanical, reversible, and **confirmed only by the check that raised it clearing afterwards**; at most **3** iterations; a snapshot per fix; **revert-on-not-cleared**; a no-progress stop; and a path guard that refuses `sushi-config.yaml`, `package.json`, `ig.ini` and LICENSE whatever a caller passes. The one class that may touch a page file must leave the file's text byte-identical, and its licence to exist at all is a provenance argument rather than a heuristic: a link to a *template* example cannot be the module's narrative, because the module's text predates the template. Exercised end to end on a fixture built from a real rendered site — three fixes applied and confirmed, and a deliberately unclearable case applied, **reverted byte-exact and escalated**, with the no-progress stop firing immediately afterwards. The guardrails assume **confident-and-wrong is the normal case**, which is this project's own record: on 2026-08-06 alone it shipped three high-confidence claims that were false (the `.po` page-title mechanism, "Simplifier is not scrapeable", and the guide-key attribute shape). A loop resting on a fixer's confidence would have amplified each; this one rests on a re-measurement and on being cheap to undo.

**2026-08-07 — the verification phase run against all four migrations, and the four defects that run exposed in the verifier itself.** The layers above were built from three known defects; running them against Dokument, Person, Consent and Labor showed that two of the six aspects a source-versus-target verification owes were not covered at all, and that two checks that *were* covered reported the right class at the wrong granularity. All four are now fixed at the cause, each with the measurement that forced it.

**(1) The reachability check could only see artefacts SUSHI generated.** `C2` iterated `fsh-generated/resources`, so an artefact supplied ready-made under `input/resources/` was rendered by the publisher and invisible to it — measured on Consent: `Parameters-mii-param-consent-manifest` renders, is listed nowhere, and the forward pass could not see it. `C2` now also scans the rendered variant for bare `<Type>-<id>.html` pages (`rendered_artifact_pages`), typed against the FHIR canonical types plus whatever types the module itself generates, because the filename alone cannot be typed — `security-and-privacy.html` splits to "security". The publisher's per-artefact *views* (`-testing`, `.change.history`, `-mappings`) are excluded by construction: counting them turned Consent's **6** unreachable SearchParameters into **30** rows of one defect. **And the granularity was wrong in the other direction:** all four modules render an `artifacts.html` that lists **no artefact at all** (Dokument 18, Person 14, Consent 20, Labor 20), which `C2` reported as 14–20 separate rows of "not listed". That is one defect, so it is now one row naming the count and the per-type breakdown.

**(2) Two aspects had no check.** **`C5` — menu and the reverse page question:** every menu entry resolving to a real page; every narrative page reachable *from* a menu; a translated `menu.xml` wherever there are translated pages (the template's own comment says a per-language copy is the only mechanism); every target page traceable to a source page or to the template's own set, which is `references/template-pages.tsv`, read from the template at tag `v0.6.0` rather than assumed; and the template's DEMO page still being present, which step 3 is supposed to delete. Measured: `translationinfo.md` is in no menu in **all four** modules — it renders, and nothing links to it. **`C6` — content placement:** `C4` asks whether a source text run exists *anywhere* in the target, which passes identically for a paragraph that landed where the migration intended and one swept into `index.md` because nothing else fitted. `C6` reports, per source page, the target pages its runs actually landed on, compared against the page map — a divergence when none landed on the mapped page, and, without a map, the ranked distribution as NICHT PRÜFBAR rather than a pass. Consent's distribution is legible on sight: `release-notes` → `changes` (19 runs), `…-uml` → `uml-diagrams` (11), `technischeimplementierung-terminologien` → `terminology` (13).

**(3) `C4`'s largest numbers were its own tooling's footprint and a rendered view.** Every harvested page opens with `<!-- Harvested from … by scripts/guide-harvest.sh -->`, long enough to pass the run-length filter, impossible to find in a target — so it reported as a lost run on all 18 Consent pages and was the **first example named in every finding**. HTML comments are now stripped before splitting. Worse: pages that embed a Simplifier element-tree rendering are not prose. Labor's `…fhir-profile-observation.md` is **121 316 non-empty lines**, of which **3 532 of 3 535** "text runs" are the rendered element tree that migration replaces with the publisher's own artefact page *by design*; across Consent and Labor that produced roughly **11 000 phantom losses**, three orders of magnitude above the real prose losses on the same pages, which it buried. Such pages are now detected by the element-table renderer's own marker — `There are no (further) constraints on this element`, measured at **0 occurrences on all 21 prose pages and 20–174 on all 7 view pages**, a separation clean enough that one occurrence is a marker rather than a threshold — and reported **NICHT PRÜFBAR** with that count, not as a pass: the prose on such a page is genuinely unchecked. Markdown table rows are excluded from the run split for the same reason and counted separately. With the noise gone the real findings are readable: Labor `index.md` 7 of 17 prose runs absent, `beschreibungmodul.md` 21 of 90, `technischeimplementierung-terminologien.md` 15 of 32.

**(4) A path label that was worse than the absolute path it avoided.** Findings name paths relative to the target, which is right while the rendered site sits inside it. Labor's preview was built outside the tree, and `os.path.relpath` produced `../../../../tmp/…` in every rendering finding. `label_path` now returns relative when inside and absolute when not.

**The claim this run did NOT confirm, recorded because a verification that only finds what it was told to find is not one.** A stale vendored template — `de.medizininformatikinitiative.template#0.5.1` against the released template `v0.6.0` — was reported as one of the defects motivating this work. Measured on 2026-08-07 via the contents API: repo tag **`v0.6.0` vendors package `0.5.1`**, tag `v0.5.1` vendors `0.3.0`, and `main` vendors `0.5.1`. So `#0.5.1` is exactly what the current release ships, and all three local modules carry it; `P1` reports IDENTISCH for all four and is right to. This is the §11.3 trap firing in the wild on a human reader, which is why `P1` and `P2` are two checks against two references rather than one. What *is* genuinely unanswerable is `P2`: no module records the template ref it was scaffolded from anywhere in the tree, so only Dokument — whose run log carries `5.2 skeleton-vendored … ref=` — can be checked at all.

**Run of record, 2026-08-07** (`--template-latest v0.6.0`; Labor against its published preview because the IG Publisher crashes on that module): Dokument 39 IDENTISCH / 15 DIVERGIERT / 14 NICHT PRÜFBAR, Person 23/7/11, Consent 22/21/29, Labor 35/29/32 — every one exit 1.

**2026-08-07 — the verification phase verified against itself: two false checks, a deleted layer, and two checks that had never returned a verdict.** The run of record above was produced by a verifier nobody had run a negative control against. Run against one — delete a real artefact, does the check that guards artefacts fire? — it returned **not_proven**. Six defects, all fixed at the cause rather than tuned, each with the measurement that forced it.

**(B1) The multi-language build's ROOT is not a language variant, and treating it as one produced this tool's own worst finding.** `variant_dirs` accepted any directory carrying an `artifacts.html`. In a multi-language build the IG Publisher writes each language into `en/` and `de/` and leaves at the root, per page name, a **~520-byte language-redirect stub** — measured: 519–534 bytes across the four modules, declaring `langs=[…]` and handing over to `assets/js/lang-redirects.js`.
